# Agent notes

Atmos is a standalone Quickshell preferences app for Omarchy. The window is QML and everything else is Rust (`atmosd`). A Rust window on ODK, `frontend/` (`atmos-ui`), is replacing the QML one page by page (`docs/adr/0013`): until the last page is ported, `bin/atmos` and `atmosd launch` still open the QML window, and the Rust one is built and tested beside it. There is no Python and there are no helper scripts: `bin/atmos` and `install.sh` are the only shell, and both hand off to `atmosd` at once (`atmosd launch`, `atmosd install`). There is no `scripts/` directory and v1 does not update installs older than v1 (`docs/adr/0017`). Do not import `qs.Ui` or `qs.Commons` from `$OMARCHY_PATH/shell`.

The design (one daemon authority, a sampling bus behind a CPU governor, a command bus for writes) and its phases are in `docs/architecture.md`, and the reasons behind each rule are the ADRs in `docs/adr/`. Read them before touching `backend/src/sampler`, `backend/src/command`, `serve.rs`, `Backend.qml` or `Ops.qml`. A decision that changes gets a new ADR that supersedes the old one; `tests/adr.test.js` keeps them well formed. The backend was called `ratmos` until `docs/adr/0018`, and the ADRs before it keep that name; read it as `atmosd`. v1 work lands on the branch `atmos-v1.0.0-rc`, and commits are GPG-signed.

## Run

- `./bin/atmos` — launch (each launch is its own window)
- `odk oma dev frontend` — the Rust window as its Bundle: `frontend/oma.toml` builds both halves, then ODK makes the Bundle, installs it over the installed copy and runs it on the desktop.
- `npm install` — oxlint and oxfmt; also sets `core.hooksPath` to `.githooks`
- `npm run lint` / `npm run fmt` — lint and format `services` and `tests`
- `./tests/frontend` — the Rust window: `cargo fmt --check`, clippy and tests in `frontend/`, which open no window. It builds on whatever ODK has checked out at `../odk` (bring it to ODK's `main` with `git -C ../odk merge --ff-only origin/main`) and says "skip" without it, and it sets `ODKD_SOCKET=none`, so the tests hear no `odkd`. When ODK's workspace version moves, `frontend/Cargo.lock` follows it in a commit of its own. Never `cargo run` it, and open it on the desktop from a test or an agent only when the owner asks for that run (`odk oma dev frontend` below): tests drive the view on GPUI's test platform (`frontend/tests/shell.rs`), and ODK's `tools/headless-shot` is how to look at it.
- `./tests/run` — oxlint, oxfmt --check, `cargo fmt --check`, `cargo clippy -D warnings`, parser tests, `tests/frontend`, plus a live snapshot check when `omarchy` is present
- `tests/sandbox.js` — any test that runs a `atmosd task` or `atmosd` goes through `createSandbox()`: throwaway HOME/XDG, a PATH of fakes that record argv (`box.calls()`), and a guard that throws on the real home or a real tool. An unscripted fake exits 97. `backendWrapper()` gives an `ATMOS_BACKEND` pinned to a fixture `--root` (atmosd only; run the app itself under `box.env()` too).
- `tests/golden/` — recorded `atmosd` replies for every op, replayed over `request` and `serve` with bodies from `Requests.js`. After an intended protocol change: `ATMOS_GOLDEN_RECORD=1 node tests/golden.test.js`, then review the diff.
- `./tests/smoke [seconds]` — opt-in: launches the real app, checks the log is clean and that one `atmosd serve` runs with no idle one-shot requests. Needs a Wayland session; run it before tagging a release.
- `./tests/file-budget` — source files stay under 800 lines. A file already past that is listed in `tests/file-budget.baseline` and may only shrink; run `./tests/file-budget --update` after a shrink, and split a file instead of raising its line.
- `./tests/bench-atmosd` — opt-in backend footprint; put new numbers in `docs/benchmarks.md` and the README Footprint table with the date, version and commit.
- pre-commit (`.githooks/pre-commit`) — `tests/partial-index-guard` (a staged file edited again fails), oxlint, oxfmt --check, `tests/file-budget`, and `cargo fmt --check` plus clippy when `backend/` is staged; skip with `git commit --no-verify`

## Rules

- Mutations go through `omarchy` commands, `atmosd task <name>` (`backend/src/tasks`, privileged steps re-exec as `atmosd root <task>` through sudo or pkexec; a passwordless sudo grant ends on its timer, on `sudo-off` or at the next boot, `docs/adr/0019`), or the Hyprland sentinel writers in `backend/src/hyprland` (`atmosd sentinel <kind> apply|list|reset`). New work is a Rust task, never a script.
- Do not write a private prefs store.
- The Rust window (`frontend/`) is built from `odk::prelude` components alone: no `odk::gpui`, no `div()`, no literal colour or size, no component modified in place (`frontend/tests/purity.rs` reads `frontend/src`). What it lacks is added to ODK (`../odk`, its own rules and ADRs), as `sidebar_frame`, `content_column` and `scroll_y` were. It reaches `atmosd` only through `frontend/src/client.rs` (one `atmosd serve`, a future per request, one channel of notices, no polling), and what it copies from the QML app (ops, hubs, titles, groups) is pinned by `frontend/tests/pins.rs`. The same rules as the QML window apply to what it sends: typed writes and `Requests`-style bodies, never a command line. It is packed as an `.oma` Bundle with `atmosd` in it and the daemon declared in `frontend/manifest.toml` (`docs/adr/0014`, `docs/oma.md`; ODK's ADR 0050): the daemon is `atmosd daemon --with-sampler`, which starts `atmosd sampler --owned` as its own child at the lowest priorities and never in the daemon process (`backend/src/sampler/owned.rs`); the bundled `atmosd serve` runs sandboxed with `ATMOS_NO_AUTOSTART=1` and `ATMOS_SESSION=daemon`, so it sends no environment and the daemon runs commands, jobs and settings topics in its own (`sampler::client::or_own_env`; a child is never given an empty one). Test a Bundle only under a home of its own with every `XDG_*_HOME` in it, a `systemd-run` of your own first on `PATH`, and ODK's `tools/headless-shot`: `odk oma install` writes the consent record into `$XDG_DATA_HOME`, which is your real one when it is set. Ported pages: Sentinel (`frontend/src/pages/sentinel.rs`; its logic is `sentinel.rs`, `live.rs` and `actions.rs`, and `frontend/tests/sentinel_parity.rs` runs the real `services/Sentinel.js` and `LiveStats.js` against it, so a change to either side fails until the other follows), Tweaks (`frontend/src/pages/tweaks.rs`; its logic is `tweaks.rs`, held to `services/Tweaks.js`, which `pages/TweaksPage.qml` asks for its on state and its writes, by `frontend/tests/tweaks_parity.rs`), Defaults (`pages/defaults.rs`; `defaults.rs`, held to `services/Defaults.js` and the QML page's steps by `defaults_parity.rs`), Favorites (`pages/favorites.rs`; `favorites.rs`, held to `services/Favorites.js` by `favorites_parity.rs`), and Drivers (`pages/drivers.rs`; `drivers.rs`, held to `services/Hardware.js` and the QML page by `drivers_parity.rs`). A page that reads an inventory reads it from the one `Inventories` (`frontend/src/inventory.rs`), and a page that runs a job hands it to the one `Jobs` (`frontend/src/jobs.rs`): one job at a time, a job whose registry entry runs as root waits for sudo mode behind the shell's password prompt (`pages/sudo.rs`, then `sudo.enable`, then `passwordlessSudo` read back), and a failure is a toast in `Failure.applyBanner`'s words; `pins.rs` holds each job's sudo flag to its entry's `.root()`. A ported page declares its searchable rows, keywords and all, in its logic module (`search::Row`), and `frontend/tests/search_parity.rs` holds them to what `search.query` reads from its QML page (`docs/adr/0020`); add a hub to `app::PORTED` when it gets a page. Every other hub and hub page is drawn from the catalog (`frontend/src/catalog/`, `pages/catalog.rs`, `docs/adr/0021`): its QML page's groups and literal rows in order, held to `search.query` both ways by `catalog_parity.rs`, with a hub's pages as tabs; a port takes its hub out of the catalog. A catalog row is *mapped* (gets a `Control`) only when what it sends can be checked under Node: `catalog_controls.rs` runs the generic paths (`writeHyprLook`, `writeHyprInput`, `set`, a typed write, a link) and holds each row to its QML block both ways, and `catalog_setters.rs` runs `Omarchy.qml`'s own setter for a row that calls one (`catalog/setter.rs`). Page logic (a dialog, a draft, a confirm, a guarded or sudo write, a row built from a model) is a `Custom` row or a `List` that the page module draws (`pages/<page>.rs`, logic in `src/<page>.rs`), held to the QML page's own code by `catalog_<page>.rs`, and its setter calls are samples in `catalog/sample_pages.rs` that `catalog_setters.rs` runs. QML-built words are `Line::varies`, `Line::words` (`catalog/words.rs`, held by `catalog_words.rs`) or a custom row that speaks; `catalog_parity.rs` fails a whole page whose QML words are not drawn. A group the QML hides goes in `catalog::SHOWN`, one it keeps out of the catalog but the window draws in `catalog::UNLISTED`, and a page waiting on ODK or the backend in `catalog::BLOCKED` with why. A catalog page that draws live samples holds `live` at the window's interval (`feed.rs`; `stats.rs` is `LiveStats.js`, held by `stats_parity.rs`). A chart the QML paints is laid out as `Charts.js` lays it out and drawn on ODK's `Chart` (held by the `*charts_parity.rs` tests), and the Omafile is `Settings.js` restated in `src/omafile/`, its `settingsCatalog()` copied into `table.rs` (held by `omafile_parity.rs`). A key a mapped row reads goes in `catalog::control::KEYS` with its topic. Every settings row has a star (`row::Stars`), which waits for the `favorites` key and writes the whole list, so a settings page also holds the topic of that key (`starred` in `app.rs`). `hubs.rs` carries each hub's description and pages, pinned to `Hubs.js` under Node. A settings page names the keys it reads (`HELD`), reads them from the one `Settings` every page shares (`frontend/src/settings.rs`, which also sends a write and takes in its read-back), and draws rows with `pages/row.rs`; `pins.rs` holds each page's keys to the topics that own them, and page tests open the window through `tests/common/window.rs`. A page holds the live feed only while it is shown (`wanted` in `frontend/src/app.rs`), and a signal or a limit goes out as a typed `write` or `settings.set`, never a command.
- Hyprland drop-in is `~/.config/hypr/atmos.lua` required as `hypr.atmos` next to `hypr.omafetch`, before `default.hypr.toggles`. `hypr.atmos_layout` wraps dwindle `layoutmsg` so scrolling workspaces do not throw. Sentinel blocks are `-- atmos:look|input|autostart|bindings|windows|workspaces begin/end` in `atmos.lua` / `looknfeel.lua` / `input.lua` / `autostart.lua` / `bindings.lua`, and `-- atmos:monitors begin/end` in `monitors.lua`.
- A `PACKAGED` file in the app root marks a package-manager install: no Check/Update, no writes under the app root. Per-user Hyprland setup is opt-in through `atmos --setup` (`atmosd task setup-atmos`); never run it implicitly from the app.
- Theme colors come from `~/.local/state/omarchy/current/theme/{colors,shell}.toml` and `~/.config/omarchy/shell.toml`.
- Diagnostics and the hardware, disk, service, app, and live inventories are Rust (`backend/src/inventory`). Copy/save/agent append `omarchy-debug --no-sudo --print` through `atmosd task diag-report`.
- Keep parsers in `services/*.js` so Node can test them without Quickshell.
- Do not import `qs.Ui`. Restyle Qt Quick Controls through `Prefs*` wrappers. Visual language lives in `services/Theme.qml`; use those tokens instead of one-off sizes.
- QML reaches `atmosd` only through `services/Backend.qml` with bodies from `services/Requests.js`. Do not add a `Process` that runs `atmosd request`, and do not poll with a `Timer`: watch through `Backend.watch` and listen for `Backend.stamp|chrome|accounts`, and hold display kinds and the five settings topics through `Backend.subscribe` and listen for `Backend.sample` (the daemon pushes `live`, with `sampledAt`; rates run on it, never on `Date.now()`; `services/DisplayFeed.qml` and `SnapshotFeed.qml` are the two listeners). The window reads no snapshot group and queues no read: a Refresh button is `snapshot.invalidate` (`Omarchy.scheduleRefresh`), the daemon invalidates what a write or a job changes and watches the files a topic is read from, and a failed tool is a key in `_failed`, never a default (`docs/adr/0011`). A job or an interactive tool is a registry entry too (`backend/src/command/entries.rs`: `Job`, `Interactive`, `Launch`): send it with `Requests.job` through `Omarchy.runJob` or `runInteractive`, and the daemon runs it as a unit that outlives the window (`docs/adr/0009`). The window builds no command line and starts no process: `tests/bus-conformance.baseline` is zero and may not rise, and `tests/writes-registry.test.js` checks every `Requests.job` name and literal argument against `atmosd job-check`. A write that changes what the window shows is a typed write, never a patch the window builds: add an entry to `backend/src/command/writes.rs` (arguments checked, command built, lane, the snapshot keys to read back, what a settled read-back looks like), send it with `Requests.write` through `runCommand`'s `op` option, and the window shows the reply's `snapshot` (`services/Ops.qml`). A setting written through `settings.set` names `readback` keys the same way. Every key must be owned by a producer in `backend/src/snapshot/keys.rs`, and every producer belongs to a topic there (a `match` with no wildcard); `tests/writes-registry.test.js` fails on a key that is not owned. A producer reads its tool with `sh::must` where the answer is the value, so a failure is reported and not shown as `""`. A new op needs its `Request` variant in `backend/src/request.rs` its builder in `Requests.js` (`tests/requests.test.js` checks the two lists match), and its row in `docs/protocol.md` (`tests/protocol-doc.test.js` checks it).
- Rust errors are `crate::error::Error` (kind + message + context), never `String`. Child processes go through `crate::runner::Run`, file replacement through `crate::fsutil::atomic_write`, and user-chosen paths through `host::confine`.
- `atmosd daemon` (`backend/src/sampler`, unit `packaging/atmosd.service`) owns the six display kinds, and background collection runs only in `atmosd sampler` (unit `packaging/atmosd-sampler.service`, idle priority, behind `sampler/governor.rs`): never add background CPU to the daemon process, which answers windows. Samples go to `$XDG_RUNTIME_DIR/atmos`; `display::load` reads that cache and asks the daemon for a missed kind with interactive priority, and a terminal command collects inline when there is no daemon, while a window's `serve` fails with `unavailable` and says so with a `backend` event: nothing in a window collects, watches or runs a write itself (`docs/adr/0010`; `Backend.qml` has no one-shot, `components/BackendUnavailable.qml` is the one screen). Keep `live` at a one-second max age (a reader must never be served one sample twice; the window's rates run on `sampledAt`, and only a terminal read stamps with its own clock), and call `sampler::drop_kinds` from any new path that mutates what an inventory shows. `serve` reads nothing itself: the daemon runs every request a window sends except the three that only ask it for what it holds (`docs/adr/0012`, `backend/tests/serve.rs`), and a new op needs no special handling for that. The settings snapshot is five topics the daemon holds, collected on demand and never on a clock (`backend/src/sampler/settings.rs`); a cached topic is sent to a window only when the files it is read from have not moved since the daemon last looked, and it looks before every hold (`docs/adr/0015`). After a write, the topics that hold the keys it names are made current, and a stored value never covers a live reading (`docs/adr/0016`, `snapshot::merge::stored`). `serve` starts a daemon when none answers and keeps looking for one for as long as the window lives; `ATMOS_NO_AUTOSTART=1` forbids that (`tests/sandbox.js` sets it), and a test that spawns `atmosd serve` without `--root` sets it too. A test that runs `setup-atmos` or `install` stubs `systemctl` and sets `XDG_CONFIG_HOME` and `XDG_RUNTIME_DIR`, or it reaches the real user manager.
- Do not launch floating terminals for settings work. Long jobs use `Omarchy.runJob` and tools that need the user's session use `Omarchy.runInteractive`; no page starts a `Process`.
- Concurrent Atmos windows are allowed. Writers serialize with flock + atomic rename (`backend/src/hyprland` `_patch` merge, shared `shell.json` lock, and sidecar locks on env/hyprsunset/tweaks/avatar/presentation). Do not reintroduce `instance-lock.sh`, `lostInstanceLock`, `quickshell -n`, or launcher `focus_existing`.
